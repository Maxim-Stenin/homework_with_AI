## Известные проблемы

- **Запреты в `.claude/settings.json` не действуют.** Контрольный запуск заведомо
  запрещённой команды `git clean -n` выполнился вместо блокировки. Наиболее вероятная
  причина: папки `.claude/` не существовало на старте сессии, и наблюдатель за настройками
  её не подхватил. **Пока это не перепроверено после перезапуска, запреты живут только
  в тексте `AGENTS.md`, то есть держатся на дисциплине, а не на механизме.**
- Часть II `AGENTS.md` содержит незаполненные места, помеченные `TODO(сессия 2)`:
  стек объекта, команды запуска стенда, порт, раннер автотестов, папка объекта.
  Часть определилась фактом создания объекта (папка `app/`, чистые HTML/CSS/JS,
  отдельный стенд не нужен), но **в файле пометки не тронуты**: раннер автотестов
  не выбран, и это решение человека. Проставить при выборе раннера.
- **Расхождение описания и реализации, известное с момента создания объекта:**
  «история транзакций пишется в CSV-файл» — файл появляется только по нажатию
  «Сохранить CSV», сама по себе история живёт в `localStorage`. Браузер не может
  писать на диск без участия человека. В сессии тестирования завести как расхождение,
  а не списать на «так и задумано».
- В `AGENTS.md` недостаточно явно разведены роли в правиле «останавливайся и спрашивай».
  По первому промпту сессии 2 агент остановился с вопросами о деталях объекта —
  формально по правилу, по сути неверно: договорённости об углах убивают материал
  для находок. Правило работает для роли тестировщика, не для создания объекта.
- Текст задания извлечён из PDF самодельным скриптом. Моноширинные фрагменты
  (имена файлов, команды, ссылки) искажены и восстанавливались по контексту —
  есть риск неверно прочитанной детали именно в них.
- Конфликт в постановке разрешён допущением: пет-проект человека и объект тестирования —
  разные вещи. Объект создаётся отдельной сессией и руками не правится. Если допущение
  неверно, переигрывать нужно до наивного прогона.
