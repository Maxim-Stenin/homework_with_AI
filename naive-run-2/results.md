## Как читать доказательства

Действия выполнялись двумя способами: настоящими кликами и нажатиями клавиш через
браузерную панель — там, где важно поведение пользователя (кнопка «Добавить»,

Приложение хранит историю в `localStorage` под ключом `finance.csv` в виде CSV
с шапкой `date,type,category,amount,comment` — это видно пользователю и без кода.

## BUG-001 — Загрузка любого файла молча стирает всю историю. Блокер

**Шаги.**
1. Добавить запись: расход, 777, «Важное», 05.05.2026, комментарий «не потерять».
2. Нажать «Загрузить CSV».
3. Выбрать любой файл с расширением `.csv`: с мусорным текстом, пустой, только
   с шапкой, HTML-файл, файл с переставленными колонками, файл из русского Excel
   с разделителем `;`.

**Ожидаемо.** Либо импорт отклоняется с сообщением об ошибке и данные остаются
на месте; либо, если замещение задумано, — предупреждение «текущие записи будут
заменены» до, а не после.

**Фактически.** История пуста, итоги обнулены, диаграмма показывает «Пока нечего
показывать». Никакого сообщения. Отмены нет.

**Доказательство.** До импорта файла `notes.csv` с содержимым `мусор\nмусор`:

```
строк в таблице: 1
localStorage: date,type,category,amount,comment
              2026-05-05,expense,Важное,777.00,не потерять
```

Сразу после:

```
строк в таблице: 0
сообщение:      "" (блок role=alert пуст)
localStorage:   date,type,category,amount,comment
на экране:      «Записей пока нет.»
```

**Почему блокер.** Единственное хранилище данных пользователя уничтожается одним
ошибочным кликом в диалоге выбора файла, без подтверждения, без сообщения
и без возможности вернуть. Замещение происходит даже тогда, когда файл вообще
не удалось разобрать, — то есть ошибка разбора трактуется как «в файле ноль
записей». См. также BUG-006: самый вероятный способ нарваться — не мусорный файл,
а собственный экспорт, открытый и пересохранённый в Excel.

## BUG-002 — Отрицательные суммы из CSV принимаются и ломают итоги. Серьёзный

**Шаги.** Загрузить файл:

```csv
date,type,category,amount,comment
2026-01-01,expense,Кафе,-10,
```

**Ожидаемо.** Строка отклонена: через форму отрицательную сумму ввести нельзя,
приложение отвечает «Введите сумму больше нуля».

**Фактически.** Запись принята.

```
таблица: 01.01.2026 | Кафе | − -10,00 ₽ | ×
итоги:   Доходы 0,00 ₽ | Расходы -10,00 ₽ | Остаток 10,00 ₽
```

Двойной минус в ячейке, отрицательная сумма расходов и остаток, выросший
от траты. Форма и импорт валидируются по разным правилам, хотя пишут в одно
хранилище.

## BUG-003 — Дата из CSV не проверяется. Серьёзный

**Шаги.** Загрузить файл:

```csv
date,type,category,amount,comment
не-дата,expense,Кафе,10,
```

**Фактически.** Строка принята, в колонке «Дата» отображается `не-дата`.

```
таблица: не-дата | Кафе | − 10,00 ₽ | ×
```

Значение попадает в сортировку истории и в хранилище. Форма при пустой дате
отвечает «Укажите дату», то есть проверка есть, но только в форме.

## BUG-004 — Импорт не сообщает ни об успехе, ни об ошибке. Серьёзный

**Шаги.** Загрузить любой файл — валидный или битый.

**Фактически.** Блок сообщений (`role=alert`) остаётся пустым во всех
11 проверенных вариантах: мусор, пустой файл, только шапка, битая дата,
отрицательная сумма, нечисловая сумма, неизвестный тип, недостающие колонки,
CRLF+BOM, переставленные колонки, HTML-файл.

**Почему это отдельный дефект.** В связке с BUG-001 пользователь не может отличить
«файл загрузился, в нём было пусто» от «файл не разобрался и я потерял всё».
Обратная связь есть у формы («Введите сумму больше нуля», «Укажите дату»),
но не у импорта — самой опасной операции в приложении.

## BUG-005 — Enter в форме не добавляет запись. Серьёзный

**Шаги.**
1. Заполнить «Категория» = `EnterTest`, «Дата» = 06.06.2026.
2. Настоящим кликом встать в поле «Сумма, ₽», настоящими нажатиями набрать `42`.
3. Нажать Enter.

**Ожидаемо.** Запись добавляется: это форма с кнопкой типа `submit`,
Enter в текстовом поле — стандартный способ отправки.

**Фактически.** Ничего не происходит: строк в таблице по-прежнему 3, сообщения
об ошибке нет, значения полей на месте. Повторное нажатие — тот же результат.

**Доказательство.** Навешен слушатель на `keydown` документа и на `submit` формы,
после чего нажат Enter:

```
перехвачено: ["Enter"]        // клавиша до поля дошла
события submit:  нет
активный элемент: fAmount
строк в таблице: 3 (было 3)
```

То есть клавиша доставлена в поле, но отправка формы не происходит. Ввод денег —
это ввод с клавиатуры, и обрыв на последнем шаге бьёт по самому частому сценарию.

## BUG-006 — Выгруженный CSV не открывается в русском Excel, а возврат стирает историю. Средний

**Оракул — текст самого приложения** под таблицей: файл `transactions.csv`
«можно открыть в Excel и вернуть обратно кнопкой „Загрузить CSV“».

**Шаги.** Нажать «Сохранить CSV», посмотреть содержимое файла.

**Фактически.** Файл `transactions.csv`, `text/csv;charset=utf-8`:

```
date,type,category,amount,comment
2026-06-01,expense,Продукты,1200.00,
2026-06-02,income,Зарплата,50000.00,аванс
```

Три расхождения с обещанием — для русской локали Excel:

1. **Нет BOM** (проверено: первый символ не `U+FEFF`) — кириллица открывается
   кракозябрами.
2. **Разделитель `,`**, а Excel в русской локали ждёт `;` — вся строка попадает
   в одну колонку.
3. **Десятичная точка** — суммы читаются как текст, а не как числа.

**И обратный путь замыкает круг.** Файл, пересохранённый русским Excel'ем,
выглядит так:

```csv
date;type;category;amount;comment
2026-06-01;expense;Продукты;1200,00;
```

Загрузка такого файла (шаг «вернуть обратно» из подписи) даёт: 0 строк, пустые
итоги, никакого сообщения — то есть **BUG-001 на собственных данных
пользователя**, ровно по инструкции, напечатанной в интерфейсе.

## BUG-007 — Длинная категория без пробелов ломает вёрстку страницы. Средний

**Шаги.** Добавить расход с категорией
`Очень-длинная-категория-без-пробелов-которая-должна-переноситься-или-обрезаться-иначе-сломает-вёрстку`.

**Фактически.** Появляется горизонтальная прокрутка всего документа.

```
documentElement: scrollWidth 934 при clientWidth 696
выходят за границу: UL.legend → LI → SPAN.name (и далее .sum, .pct)
```

Виновник — подпись категории в легенде диаграммы: длинное слово не переносится
и распирает страницу. Таблица при этом держится.

**Примечание.** На ширине 375×812 с обычными данными вёрстка не разъезжается
(`scrollWidth == clientWidth == 375`), мета-тег viewport на месте. Дефект именно
в длинной неразрывной строке, а не в мобильной вёрстке.

## BUG-008 — Нет верхней границы суммы, точность теряется молча. Средний

**Шаги.** Добавить расход на `999999999999999999999`.

**Фактически.** Запись принята.

```
в хранилище: 2026-08-16,expense,Кафе,999999999999999868928.00,
на экране:   − 999 999 999 999 999 900 000,00 ₽
```

Сохранённое число не равно введённому — потеря точности при разборе. Карточки
итогов и легенда распираются двадцатизначной суммой.

## BUG-009 — Сумма меньше половины копейки проходит проверку «больше нуля». Средний

**Шаги.** Добавить расход на `0.004`, затем на `0.0000001`.

**Ожидаемо.** Отказ с тем же сообщением, что и для нуля: сумма, которая
после округления до копеек равна нулю, — не «больше нуля».

**Фактически.** Обе записи приняты без сообщения.

```
таблица:     06.06.2026 | Нано  | − 0,00 ₽ | ×
             06.06.2026 | Микро | − 0,00 ₽ | ×
в хранилище: 2026-06-06,expense,Микро,0.00,
             2026-06-06,expense,Нано,0.00,
итоги:       не изменились
```

Строки-пустышки, которые невозможно объяснить пользователю: сумма нулевая,
а сообщение при вводе нуля прямо запрещает ноль.

## BUG-010 — Удаление записи без подтверждения и без отмены. Средний

**Шаги.** Нажать «×» в строке истории (настоящий клик).

**Фактически.** Запись исчезает немедленно, хранилище перезаписывается,
вернуть нечем. Диалога подтверждения нет.

**Что при этом работает правильно** (проверено отдельно): удаляется именно
та строка, на которую нажали. Из трёх полностью одинаковых записей
(100 ₽, Кафе, 10.08.2026, «дубль») удаление первой оставило ровно две,
итоги пересчитались с 300 до 200 ₽. Ошибки выбора строки нет.

## BUG-011 — Неизвестный тип операции из CSV молча считается расходом. Мелкий

**Шаги.** Загрузить файл со значением типа `трата` вместо `expense`/`income`:

```csv
date,type,category,amount,comment
2026-01-01,трата,Кафе,10,
```

**Фактически.** Строка принята и учтена как расход, без сообщения. Любая опечатка
в колонке `type` даёт расход, в том числе опечатка в слове `income` — то есть
доход способен превратиться в расход при переносе файла.

## BUG-012 — Категории различаются регистром. Мелкий, спорный

**Шаги.** Добавить три расхода с категориями `Кафе`, `кафе`, `КАФЕ`.

**Фактически.** Три отдельные категории в легенде:

```
кафе 0,20 ₽ 65% | Кафе 0,10 ₽ 32% | КАФЕ 0,01 ₽ 3%
```

Разбивка по категориям — главная ценность экрана, а опечатка в регистре
рассыпает одну статью расходов на несколько. Поле категории — свободный ввод
без подсказок из ранее введённых значений, так что промахнуться легко.

**Почему спорный.** Регистрозависимость может быть сознательным решением;
без `SPEC.md` не решается.

## BUG-013 — Поле «Дата» не подставляет сегодняшнее число и залипает на прошлом. Мелкий, спорный

**Фактически.**

1. При первом открытии поле «Дата» пустое; попытка добавить запись даёт
   «Укажите дату».
2. После успешного добавления поля «Сумма», «Категория» и «Комментарий»
   очищаются, а «Дата» сохраняет предыдущее значение.

Второе поведение полезно при вводе пачки записей одним днём и вредно на следующий
день: запись молча уходит вчерашним числом. В связке с пунктом 1 (никакого
значения по умолчанию) типовой сценарий «записать сегодняшнюю трату» требует
ручного заполнения даты каждый первый раз.

---

## BUG-014 — Экспоненциальная запись и знак «плюс» принимаются как сумма. Мелкий, спорный

**Фактически.** Приняты и сохранены: `1e3` → 1000,00 ₽; `+100` → 100,00 ₽;
`1 000` (с пробелом) → 1000,00 ₽. Отклонены корректно: пусто, `0`, `-100`,
`abc`, `Infinity`.

`1 000` с пробелом-разделителем разрядов — скорее удобство, чем дефект.
`1e3` в поле «Сумма, ₽» — почти наверняка опечатка, а не намерение,
и молча превращать её в 1000 ₽ рискованно.

## BUG-015 — Доли в легенде дают 99%. Мелкий

**Шаги.** Три расхода по 10 ₽ в категориях A, B, C.

**Фактически.** `A 33% | B 33% | C 33%` — в сумме 99%. Косметика: округление
каждой доли по отдельности без распределения остатка.

## Что работает

Проверено и подтверждено:

- **Основной сценарий.** Добавление расхода и дохода, пересчёт карточек
  «Доходы / Расходы / Остаток», построение диаграммы и легенды, переключение
  «Расходы по категориям» ↔ «Доходы по категориям», пустое состояние при
  отсутствии данных нужного типа.
- **Арифметика.** `1 000 000,01 − 0,31 = 999 999,70` — сходится; итоги, таблица
  и легенда согласованы между собой.
- **Сохранение между сессиями.** 13 записей пережили перезагрузку страницы
  без искажений.
- **Экранирование HTML.** Категория `<img src=x onerror="...">` и комментарий
  `<b>bold</b>` выводятся как текст и в таблице, и в легенде диаграммы;
  внедрённый код не выполнился.
- **Кавычки и запятые в CSV.** Категория `Кат"с,запятой` и комментарий
  `строка; с "кавычками", и =CMD()` квотируются и удваиваются по правилам CSV,
  выгрузка и обратная загрузка не рассыпают колонки.
- **Удаление нужной строки** среди полностью одинаковых записей (см. BUG-010).
- **Устойчивость к битому хранилищу.** Подложенный в `localStorage` мусор
  (`2026-13-45`, строка без запятых, пустые поля) приложение не роняет:
  форма жива, итоги нулевые, ошибок в консоли нет.
- **Мобильная ширина 375×812** с обычными данными — без горизонтальной прокрутки.
- **Консоль чистая** за весь прогон: ни одной ошибки.
- **Сортировка истории** — по дате убыванию, внутри одной даты новые сверху.
  Дефектом не считаю.

## Что не проверялось

- Реальное скачивание файла кнопкой «Сохранить CSV» — перехвачено содержимое
  `Blob` и имя файла, но сам файл на диск не сохранялся.
- Скриншоты — панель браузера в этой сессии не отрисовывала кадры,
  все визуальные выводы сделаны по геометрии DOM.
- Поведение при недоступном или переполненном `localStorage` (режим инкогнито,
  превышение квоты).
- Синхронизация между двумя вкладками.
- Клавиатурная навигация целиком и доступность для скринридера — проверена
  только привязка `label` к полям (все пять привязаны корректно) и Enter (BUG-005).
- Кросс-браузерность: прогон шёл в одном браузерном движке.
- Производительность на больших объёмах — максимум 13 записей.
- Сверка со `SPEC.md` — запрещена условиями прогона.
